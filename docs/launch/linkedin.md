# LinkedIn post

Ten years in kitchens taught me one rule that outlived the career: mise en place. Everything prepped, labeled and in reach before the first ticket prints. Nobody figures out the sauce during service.

I started running coding agents on real projects this year and watched them skip that rule every time. Code first, think about risk never, review by re-reading the diff and calling it fine. Every review clean, and the problems still there when I read the diff myself.

SolomonLoop is mise en place for coding agents. A Claude Code plugin, nine steps: define, research, assess risk, implement, verify, challenge, learn, validate, promote. The implementer writes a Risk section before any code. The reviewer tries to break each claim and reports HELD or BROKE with a file and line. Findings become lessons, and a lesson changes the rules only after it recurs in two separate task groups. One occurrence is a candidate, not evidence.

It first ran on top of obra/superpowers and still defers to it when loaded. MIT, nothing leaves your machine, installs in two commands.

I am a CS senior at CSUSB. This is the process I use for my own work, packaged. If you run agents on real code, try it on one plan and send me the BROKE lines.
